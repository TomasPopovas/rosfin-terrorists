# rosfin-terrorists — мониторинг перечней Росфинмониторинга

Утилита на Go, которая сама заходит в личный кабинет Росфинмониторинга
([portal.fedsfm.ru](https://portal.fedsfm.ru)), проверяет обновления перечней
и скачивает **только то, что действительно изменилось**. По итогам каждой
проверки она отправляет отчёт на почту.

Работает как демон в Docker: на любом Linux-хосте или на Synology NAS через
Container Manager. Можно запускать и разово, без Docker.

> Версия 2. Первая версия качала только перечень по терроризму (сначала dbf,
> потом xml/doc) каждые 12 часов. Теперь утилита отслеживает все пять разделов
> кабинета, проверяет изменения, хранит состояние между запусками и шлёт письма.

## Что отслеживается

| № | Раздел кабинета | Имя в настройках | Как проверяется | Что скачивается |
|---|---|---|---|---|
| 1 | Перечень организаций и физических лиц, причастных к экстремистской деятельности или терроризму | `xml`, `doc` → папка `terrorism/` | по уведомлению `FedsfmPortal.NewTerroristCatalog` | `GET /SkedDownload/GetActiveSked?type=xml21` и `?type=doc`: zip с XML (схема 2.1) и Word |
| 2 | Перечень лиц, в отношении которых действует решение МВК о замораживании | `mvk` → `mvk/` | по уведомлению `FedsfmPortal.NewMvkCatalog` | `GET /XmlCatalogDownload/GetActiveMvk` |
| 3 | Решения судов о приостановлении операций | лента `court` | по дате верхнего сообщения в списке | ссылка на раздел в письме (см. [Ограничения](#ограничения)) |
| 4 | Перечни Совета Безопасности ООН | `oon-rus`, `oon-eng` → `oon/` | по уведомлению `FedsfmPortal.SbOonCatalog` | `GET /XmlCatalogDownload/GetActiveOONRus` и `GetActiveOONEng` |
| 5 | Информация Росфинмониторинга (новости ПОД/ФТ) | лента `info` | по дате верхнего сообщения в списке | ссылка на раздел в письме |

Каталоги 1, 2 и 4 скачиваются файлами. По лентам 3 и 5 утилита фиксирует
появление нового сообщения и присылает прямую ссылку на раздел кабинета.

## Как это работает

1. **Вход.** Утилита логинится в кабинет по логину и паролю из `.env`.
   Если сессия протухла и портал вместо файла отдаёт HTML страницы логина,
   это распознаётся как ошибка: мусор на диск не сохраняется.
2. **Проверка каталогов.** Один запрос `POST /EventNotifications/GetNotifications`
   возвращает ленту событий кабинета. Для каждого каталога берётся дата самого
   свежего уведомления (`createDate`) и сравнивается с той, что сохранена
   в `state.json`.
3. **Проверка лент.** Для лент «Решения судов» и «Информация» запрашивается
   список (`POST /CommandManager/Execute`), и дата верхнего сообщения
   сравнивается с сохранённой.
4. **Ничего не изменилось** — папка не создаётся, файлы не качаются. Если
   включено `ROSFIN_MAIL_ON_QUIET`, приходит короткое письмо «изменений нет».
5. **Что-то изменилось** — создаётся папка с датой и временем, в неё качаются
   только обновлённые разделы. Архивы распаковываются, пишется `manifest.json`
   с sha256, обновляется ссылка `latest`.
6. **Отметка «прочитано».** Уведомления кабинета помечаются прочитанными только
   по тем разделам, которые реально скачались. Так робот ведёт себя как человек:
   зашёл, увидел новое и забрал его.
7. **state.json** обновляется только по успешно скачанным разделам, поэтому
   неудачная загрузка повторится при следующей проверке.
8. **Письмо** с итогами: что обновилось, что без изменений, где ошибки.

**Расписание.** Утилита работает без cron и планировщика DSM, расписание живёт
внутри контейнера. По умолчанию проверка идёт дважды в день, в окна
**09:00–10:00** и **17:00–18:00** (время московское, `TZ=Europe/Moscow`).
Минута внутри окна выбирается случайно, чтобы не стучаться на портал всегда
в одно и то же время. Окна настраиваются переменной `ROSFIN_WINDOWS`.

**Ошибки не роняют демон.** Неудачный прогон логируется и отправляется письмом,
после чего процесс ждёт следующего окна. Загрузки повторяются до 3 раз
с паузой 5 с → 10 с → 20 с.

## Куда что вписывать

Все личные данные лежат **только в файле `.env`** рядом с `docker-compose.yml`.
Файл `.env` указан в `.gitignore` и в репозиторий не попадает. Шаблон
находится в [`.env.example`](.env.example):

```bash
cp .env.example .env
```

| Переменная в `.env` | Что вписать | Обязательно |
|---|---|---|
| `ROSFIN_LOGIN` | логин личного кабинета portal.fedsfm.ru | **да** |
| `ROSFIN_PASS` | пароль личного кабинета | **да** |
| `ROSFIN_SMTP_HOST` | имя почтового сервера, например `mail.example.ru` (по нему проверяется TLS-сертификат) | для почты |
| `ROSFIN_SMTP_ADDR` | IP или имя, по которому реально подключаться, если оно отличается от `SMTP_HOST` (например, внутренний IP сервера в LAN). Можно оставить пустым | нет |
| `ROSFIN_SMTP_PORT` | порт SMTP, обычно `587` (STARTTLS) | нет, по умолчанию 587 |
| `ROSFIN_SMTP_USER` | ящик-отправитель, например `robot@example.ru` | для почты |
| `ROSFIN_SMTP_PASS` | пароль от ящика-отправителя | для почты |
| `ROSFIN_MAIL_TO` | кому слать отчёты | для почты |

Если не заполнено хоть одно из `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`,
`MAIL_TO`, письма не отправляются, а скачивание работает как обычно.
В логе при старте будет строка «почтовые уведомления выключены».

Всё остальное (окна проверки, разделы, хранение) задаётся в блоке
`environment:` файла `docker-compose.yml`. Там нет секретов, и его можно
спокойно править. Полный список — в разделе [Все настройки](#все-настройки).

Путь к папке с выгрузками задаётся **левой частью** строки `volumes:`
в `docker-compose.yml`. Правую часть (`/data`) не трогайте:

```yaml
volumes:
  - /volume1/docker/rosfin/downloads:/data   # ← меняется только левая часть
```

## Быстрый старт (Docker)

```bash
git clone https://github.com/TomasPopovas/rosfin-terrorists.git
cd rosfin-terrorists

cp .env.example .env
nano .env                      # впишите логин/пароль кабинета и, по желанию, почту

docker compose up -d --build
docker compose logs -f
```

Файлы появятся в `./downloads`. Остановить контейнер: `docker compose down`.

Разовая проверка прямо сейчас, без ожидания окна:

```bash
docker compose run --rm rosfin-terrorists -once
```

Скачать всё принудительно, без проверки изменений:

```bash
docker compose run --rm rosfin-terrorists -once -force
```

## Установка на Synology NAS

Для NAS есть отдельный файл [`docker-compose.synology.yml`](docker-compose.synology.yml).
От обычного он отличается тремя вещами: `network_mode: host`, абсолютный путь
`/volume1/...` и строка `user:` с uid:gid пользователя DSM.

### 1. Папки

В File Station создайте:

- `/volume1/docker/rosfin/` — папка проекта (сюда лягут исходники);
- `/volume1/docker/rosfin/downloads/` — сюда контейнер будет складывать файлы.

### 2. Установка через SSH (самый предсказуемый вариант)

Включите SSH: **Панель управления → Терминал и SNMP → Включить службу SSH**.

```bash
ssh ваш_логин@адрес-nas
sudo -i

mkdir -p /volume1/docker/rosfin
cd /volume1/docker/rosfin

git clone https://github.com/TomasPopovas/rosfin-terrorists.git .
mkdir -p downloads

# конфиг для Synology вместо обычного
cp docker-compose.synology.yml docker-compose.yml

# логин/пароль кабинета и почта
cp .env.example .env
vi .env

# узнайте свой uid:gid и подставьте в строку user: в docker-compose.yml
id ваш_логин
chown -R 1026:100 downloads          # свои значения из вывода id

docker compose -p rosfin-terrorists up -d --build
docker compose logs -f
```

На DSM 7 команда называется `docker compose`, на DSM 6 — `docker-compose`.
Первая сборка занимает 2–5 минут: скачивается образ Go.

### 3. Установка через Container Manager (без SSH)

1. File Station → создайте `/volume1/docker/rosfin` и внутри `downloads`.
2. На GitHub нажмите **Code → Download ZIP** и распакуйте содержимое в
   `/volume1/docker/rosfin`. В папке должны оказаться `Dockerfile`, `go_src`,
   `certs`, `docker-compose.synology.yml`, `.env.example`.
3. Переименуйте `docker-compose.synology.yml` в `docker-compose.yml`,
   а `.env.example` — в `.env`. Откройте `.env` текстовым редактором DSM
   и впишите логин, пароль и почту.
4. **Container Manager → Проект → Создать**:
   - Название: `rosfin-terrorists`
   - Путь: `/volume1/docker/rosfin`
   - Источник: «Использовать существующий docker-compose.yml»
5. Нажмите **Далее → Готово**. DSM соберёт образ и запустит контейнер.
6. На вкладке **Журнал** появятся строки вида `демон запущен, окна: 09:00-10:00,17:00-18:00 ...`
   и `следующая проверка: ...`.

### 4. Обновление до новой версии

> ⚠️ Кнопки «Остановить/Запустить» и «Собрать» в Container Manager **не
> пересобирают** образ из новых исходников, если старый образ уже есть.
> Контейнер просто перезапустится со старым кодом.

Надёжный способ — через SSH:

```bash
cd /volume1/docker/rosfin
sudo git pull                                            # или распакуйте новый ZIP поверх
sudo docker compose -p rosfin-terrorists up -d --build
```

Без SSH: остановите и **удалите** контейнер, удалите образ
`rosfin-terrorists` на вкладке **Образ**, затем снова выполните сборку проекта.

### 5. Обслуживание

```bash
docker compose logs --tail 50                            # что происходит
docker compose restart                                   # перечитать .env после смены пароля
docker compose run --rm rosfin-terrorists -once          # разовая проверка сейчас
docker compose down                                      # остановить
```

`restart: unless-stopped` поднимет контейнер после перезагрузки NAS.
Планировщик заданий DSM настраивать не нужно.

## Что получается на диске

Папка создаётся **только когда что-то изменилось**. Внутри — подпапки
по разделам, и в них лежат только обновившиеся разделы:

```
downloads/
├── state.json                       # что и на какую дату уже забрано (не удалять без нужды)
├── 2026-10-05_17-42/
│   ├── terrorism/
│   │   ├── perechen_xml.zip         # архив как отдал портал
│   │   ├── perechen_doc.zip
│   │   ├── <имя из архива>.xml      # распакованный XML (схема 2.1)
│   │   └── <имя из архива>.doc      # распакованный Word
│   └── manifest.json                # время, размеры и sha256 каждого архива
├── 2026-10-06_18-07/
│   ├── oon/
│   │   ├── perechen_oon-rus.zip
│   │   ├── perechen_oon-eng.zip
│   │   └── ...
│   └── manifest.json
└── latest -> 2026-10-06_18-07       # относительная ссылка на последнюю выгрузку
```

`state.json` выглядит так:

```json
{
  "catalogs": {
    "mvk": "2026-06-25T12:20:58.827",
    "oon": "2026-10-06T18:00:25.837",
    "terrorism": "2026-10-05T17:37:12.613"
  },
  "feeds": {
    "court": "20.09.2022 11:11",
    "info": "07.07.2026 10:20"
  }
}
```

Если удалить `state.json`, при следующей проверке всё скачается заново.

Ссылка `latest` относительная, поэтому она работает и внутри контейнера
(`/data/latest`), и на хосте (`/volume1/.../downloads/latest`).

## Письмо с отчётом

Тема письма: `rosfin: обновлено разделов — N`, `rosfin: обновлено N, с ошибкой M`,
`rosfin: изменений нет` или `rosfin: ошибка запуска`. Пример текста:

```
Папка выгрузки: /data/2026-10-06_18-07

ИЗМЕНИЛОСЬ:
  [oon] Перечни Совета Безопасности ООН (XML, рус.)
    perechen_oon-rus.zip (0.4 МБ, sha256 3f9a1c...)
    распаковано: ...xml
  [info] Информация Росфинмониторинга (Новости ПОД/ФТ)
    появилось новое сообщение от 07.10.2026 10:20 — откройте раздел в кабинете
    открыть в кабинете: https://portal.fedsfm.ru/#eyJJZCI6...

БЕЗ ИЗМЕНЕНИЙ (не скачивалось):
  [terrorism] Перечень причастных к экстремистской деятельности или терроризму (XML 2.1)
  [mvk] Перечень лиц, в отношении которых действует решение МВК о замораживании (XML)
  ...

Итого: изменилось 2, без изменений 4, с ошибкой 0.
```

Письмо отправляется и тогда, когда изменений нет (`ROSFIN_MAIL_ON_QUIET=true`).
Это сделано намеренно: тишина в почте означает, что сломался сам мониторинг.

Тема кодируется по RFC 2047, тело — base64 UTF-8, поэтому кириллица корректно
отображается в Outlook, eM Client и Thunderbird.

## Все настройки

Каждая настройка задаётся переменной окружения (удобно для Docker)
или одноимённым флагом командной строки.

### Кабинет и скачивание

| Переменная | Флаг | По умолчанию | Описание |
|---|---|---|---|
| `ROSFIN_LOGIN` | `-login` | — | Логин личного кабинета (**обязательно**) |
| `ROSFIN_PASS` | `-password` | — | Пароль личного кабинета (**обязательно**) |
| `ROSFIN_OUTPUT_DIR` | `-output` | `./downloads` (в Docker `/data`) | Куда складывать файлы и `state.json` |
| `ROSFIN_WINDOWS` | `-windows` | `09:00-10:00,17:00-18:00` | Окна ежедневной проверки (время контейнера, см. `TZ`) |
| `ROSFIN_SOURCES` | `-sources` | `all` | Каталоги: `all` или список из `xml,doc,mvk,oon-rus,oon-eng` |
| `ROSFIN_FEEDS` | `-feeds` | `all` | Ленты: `all`, `none` или `court,info` |
| `ROSFIN_FORCE` | `-force` | `false` | Скачать всё, игнорируя проверку изменений |
| `ROSFIN_ONCE` | `-once` | `false` | Одна проверка и выход (без демона) |
| `ROSFIN_MARK_READ` | `-mark-read` | `true` | Отмечать уведомления прочитанными после скачивания раздела |
| `ROSFIN_EXTRACT` | `-extract` | `true` | Распаковывать zip рядом с архивом |
| `ROSFIN_KEEP_RUNS` | `-keep` | `0` | Сколько последних папок хранить, `0` — все |
| `ROSFIN_LATEST_LINK` | `-latest-link` | `true` | Обновлять ссылку `latest` |
| `ROSFIN_TIMEOUT` | `-timeout` | `3m` | Таймаут HTTP-запроса |
| `ROSFIN_ATTEMPTS` | `-attempts` | `3` | Попыток скачивания при ошибке (пауза 5 с, 10 с, 20 с…) |
| `ROSFIN_BASE_URL` | `-base-url` | `https://portal.fedsfm.ru` | Адрес портала (нужен только для тестов) |
| `ROSFIN_COURT_MESSAGE_TYPE` | `-court-message-type` | `67` | IdMessageType ленты «Решения судов» |
| `ROSFIN_INFO_MESSAGE_TYPE` | `-info-message-type` | `11` | IdMessageType ленты «Информация» |
| `TZ` | — | `Europe/Moscow` | Часовой пояс контейнера (влияет на окна и имена папок) |

### Почта

| Переменная | Флаг | По умолчанию | Описание |
|---|---|---|---|
| `ROSFIN_SMTP_HOST` | `-smtp-host` | — | Имя SMTP-сервера (для TLS и HELO) |
| `ROSFIN_SMTP_ADDR` | `-smtp-addr` | = `SMTP_HOST` | Куда реально подключаться (IP/имя) |
| `ROSFIN_SMTP_PORT` | `-smtp-port` | `587` | Порт SMTP; STARTTLS включается, если сервер его поддерживает |
| `ROSFIN_SMTP_USER` | `-smtp-user` | — | Логин и адрес отправителя |
| `ROSFIN_SMTP_PASS` | `-smtp-pass` | — | Пароль отправителя (держите только в `.env`) |
| `ROSFIN_MAIL_TO` | `-mail-to` | — | Получатель отчётов |
| `ROSFIN_MAIL_ENABLED` | `-mail-enabled` | `true` | Общий выключатель почты |
| `ROSFIN_MAIL_ON_QUIET` | `-mail-on-quiet` | `true` | Слать письмо и при отсутствии изменений |

## Запуск без Docker

Нужен Go 1.22+.

```bash
cd go_src
make test            # тесты
make build           # vet + test + сборка в go_src/build/
make once            # разовая проверка, файлы в ../downloads
make run             # демон с окнами проверки
make build_for_win   # rosfin-terrorists.exe для Windows
```

Makefile подхватывает `.env` из корня репозитория, так что логин и пароль
можно положить туда. Можно и передать флагами:

```bash
./build/rosfin-terrorists -login ЛОГИН -password ПАРОЛЬ -once -output ./downloads
```

При запуске без Docker в системе должны быть установлены сертификаты
Минцифры (см. ниже). Иначе подключение к порталу упадёт с ошибкой TLS.

---

## Сертификаты Минцифры

Сертификат portal.fedsfm.ru выпущен российским удостоверяющим центром
Минцифры (НУЦ), которого нет в стандартных хранилищах. Поэтому в репозитории
лежат публичные сертификаты:

| Файл | Что это |
|---|---|
| `certs/russian_trusted_root_ca.crt` | Russian Trusted Root CA (действует до 2032) |
| `certs/russian_trusted_sub_ca.crt` | Russian Trusted Sub CA, выпуск 2022 (до 2027) |
| `certs/russian_trusted_sub_ca_2024.crt` | Russian Trusted Sub CA, выпуск 2024 (до 2029), им подписан текущий сертификат портала |

`Dockerfile` копирует их в образ и выполняет `update-ca-certificates`,
так что в Docker ничего делать не нужно.

Для запуска без Docker:

- **Linux (Debian/Ubuntu):** `sudo cp certs/*.crt /usr/local/share/ca-certificates/ && sudo update-ca-certificates`
- **Windows:** установите сертификаты двойным щелчком: корневой — в
  «Доверенные корневые центры сертификации», промежуточные — в
  «Промежуточные центры сертификации». Можно также поставить их с портала
  Госуслуг.

Если портал сменит промежуточный сертификат, нужный файл можно найти
в расширении Authority Information Access его TLS-сертификата
(`openssl s_client -connect portal.fedsfm.ru:443 -showcerts`), а скачать —
на `nuc-cdp.digital.gov.ru` или gosuslugi.ru/crt.

## Решение проблем

| Симптом в логе | Причина и решение |
|---|---|
| `x509: certificate signed by unknown authority` | Не установлены сертификаты Минцифры. В Docker пересоберите образ (`up -d --build`). Без Docker поставьте их вручную, см. выше |
| `вход не выполнен: сессия не создана (проверьте логин и пароль)` | Неверный логин или пароль в `.env`, либо пароль сменили в кабинете. Исправьте `.env` и выполните `docker compose restart` |
| `не заданы логин и пароль личного кабинета` | Нет `.env` рядом с `docker-compose.yml` или в нём пустые `ROSFIN_LOGIN` / `ROSFIN_PASS` |
| `permission denied` при записи в `/data` | Папка выгрузок принадлежит другому пользователю. Подставьте свой uid:gid в `user:` или выполните `chown -R 1026:100 .../downloads`. В DSM это можно сделать разовой задачей **Планировщика** от root |
| Таймауты / `dial tcp ... i/o timeout` на Synology | На части NAS не работает NAT bridge-сети Docker. Используйте `network_mode: host` (уже стоит в `docker-compose.synology.yml`) |
| `smtp dial ...: connection refused / timeout` | Публичное имя почтового сервера резолвится во внешний адрес, где порт закрыт. Укажите в `ROSFIN_SMTP_ADDR` внутренний IP сервера, а в `ROSFIN_SMTP_HOST` оставьте имя, на которое выписан сертификат |
| `smtp starttls: x509: certificate is valid for ..., not ...` | `ROSFIN_SMTP_HOST` не совпадает с именем в сертификате почтового сервера |
| Письма с «кракозябрами» | Исправлено в этой версии: тема по RFC 2047, тело в base64 |
| Изменили код, а поведение старое | Образ не пересобрался, см. [Обновление до новой версии](#4-обновление-до-новой-версии) |
| Хочу скачать всё заново | Разово: `docker compose run --rm rosfin-terrorists -once -force`. Или удалите `downloads/state.json` |

## Ограничения

- **Ленты «Решения судов» и «Информация Росфинмониторинга».** Список сообщений
  портал отдаёт гридом DevExpress. Идентификатор сообщения (`messageId`) хранится
  во внутреннем состоянии грида, а в разметке его нет. Поэтому по этим разделам
  утилита надёжно **замечает** новое сообщение по дате, но не скачивает его само.
  В письме приходит прямая ссылка на раздел кабинета. Код для автоматического
  скачивания (`TextMessage/Open` + `TextMessage/GetFile`) уже написан: как только
  появится способ получить `messageId`, достаточно включить `CanFetch` у ленты
  в `go_src/feeds.go`.
- Утилита работает с API веб-кабинета, а не с официальным публичным API.
  Если портал поменяет внутренние адреса, понадобится обновление.
- Учётные данные кабинета принадлежат организации. Храните `.env` только
  на доверенном хосте.

## Структура репозитория

```
.
├── Dockerfile                    # двухэтапная сборка: Go → alpine + сертификаты Минцифры
├── docker-compose.yml            # обычный Linux-хост
├── docker-compose.synology.yml   # Synology NAS (host-сеть, /volume1, uid:gid)
├── .env.example                  # шаблон .env — сюда логин/пароль и почта
├── certs/                        # публичные сертификаты НУЦ Минцифры
├── go_src/                       # актуальная версия (Go, только стандартная библиотека)
│   ├── main.go                   # конфигурация, цикл проверки, логика «качать или нет»
│   ├── client.go                 # вход в кабинет, общие HTTP-помощники
│   ├── sources.go                # каталоги: terrorism, mvk, oon
│   ├── notifications.go          # лента событий кабинета, отметка «прочитано»
│   ├── feeds.go                  # ленты сообщений: court, info
│   ├── schedule.go               # окна запуска со случайной минутой
│   ├── state.go                  # state.json — что уже забрано
│   ├── storage.go                # атомарная запись, распаковка, manifest, latest, очистка
│   ├── mail.go                   # письма-отчёты, сохранение текстов и вложений
│   ├── *_test.go                 # тесты (go test ./...)
│   └── Makefile
└── py_src/                       # первая версия на Python (историческая, качает dbf)
```

`py_src/` оставлен для истории. Актуальная и поддерживаемая версия — Go в `go_src/`.
